# Политика использования AI в PMO

## Назначение
AI-инструменты используются для автоматизации рутины PMO (отчётность,
анализ рисков, сводки по портфелю), но не заменяют управленческие решения.

## Принципы
1. **Human-in-the-loop:** любое AI-сгенерированное решение проверяется
   человеком перед публикацией (статус-отчёт, риск-сводка).
2. **PII-redaction (152-ФЗ):** перед отправкой в LLM данные очищаются
   от персональных данных (ИНН, СНИЛС, паспорт, ФИО, контакты).
3. **Проверяемость:** AI-сводка должна содержать ссылки на источник
   (issue, задача, риск), чтобы её можно было проверить.
4. **Ограничение домена:** AI не принимает решений о приоритизации,
   бюджете, найме; только готовит материал для человека.
5. **Логирование:** все AI-запросы и ответы логируются для аудита.

## Сценарии использования
- Генерация статус-отчёта портфеля из данных Jira/таблиц.
- Извлечение рисков из переписки/протоколов (с проверкой человеком).
- Сводка по портфелю для руководства (с ссылками на источники).
- Проверка полноты данных (заполнены ли атрибуты портфеля).

## Метрики
- Доля AI-сгенерированных артефактов, принятых без правок.
- Экономия часов/неделю на рутине.
- Количество инцидентов с PII (цель — 0).

## Ограничения
- AI не заменяет PMO-решения.
- AI не работает с чувствительными данными без redaction.
- AI-сводки — черновик, а не финальный отчёт.
