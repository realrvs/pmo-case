# PMO-кейс: автоматизация закупок для энергетической компании

Волонтёрский/рабочий кейс построения PMO для проекта с 5 командами.
Обезличен: названия, цифры и детали изменены. Кейс основан на реальном
проекте, цифры приблизительные. Все проценты — округлённые
управленческие оценки, а не бухгалтерская точность.

## За 90 секунд

- **Контекст:** крупная энергетическая компания, автоматизация закупочной
  деятельности с нуля. 5 команд (аналитика, дизайн, фронт, бэк, QA),
  20+ человек, распределённая команда. Стек: Vue.js 3, FastAPI, PostgreSQL,
  Kubernetes. Методология: Scrumban.
- **Роль:** руководитель проектов / PMO Lead. Полный жизненный цикл:
  от планирования до **предварительных испытаний (ПИ)** — формальной вехи
  готовности системы к приёмке заказчиком.
- **Результат:** проект выведен с нуля в стадию ПИ; **ПИ пройдены,
  0 критичных дефектов, система признана готовой к приёмке**;
  доля задач, закрытых в спринте, ~60% → ~85%; незапланированные
  межкомандные блокировки −40% (оценка); переделки фронта из-за API −50%
  (оценка).

## Как читать этот репозиторий

- **5 минут:** `decision-log/002` (единая приоритизация) и `decision-log/003`
  (управление зависимостями) — два главных управленческих решения.
- **15 минут:** все 8 decision-log + `metrics/before-after.md`.
- **30 минут:** decision-log + `artifacts/` + `ai-governance/policy.md`.
- **Если вы рекрутер:** начните с этого README → `metrics/before-after.md`
  → `decision-log/006` (ресурсы) → `decision-log/007` (конфликт стейкхолдеров).

## Ключевые решения (decision-log)

| № | Решение | Что показывает |
|---|---|---|
| 001 | Scrumban вместо классического Scrum | Выбор методологии под ограничения |
| 002 | Единая точка приоритизации между 5 командами | Управление портфелем |
| 003 | Управление зависимостями фронт ↔ бэк ↔ аналитика | Работа с узкими местами |
| 004 | QA-гейт перед ПИ | Управление качеством и готовностью к приёмке |
| 005 | Change request для изменений заказчика | Управление изменениями |
| 006 | Распределение 20+ человек между 4 инициативами | Управление ресурсами |
| 007 | Конфликт заказчика и аналитики по объёму ТЗ | Медиация стейкхолдеров |
| 008 | Что не сработало: тяжёлый риск-процесс | Рефлексия и упрощение |

## Артефакты

- `artifacts/pmo-charter.md` — цели, модель, границы, принципы PMO.
- `artifacts/raci.md` — RACI на 4 критичных процесса.

## Ограничения

- Волонтёрский/рабочий формат, небольшой масштаб относительно энтерпрайза.
- Цифры приблизительные; точные значения — по данным Jira/Confluence.
- Детали обезличены; коммерческие цифры и названия систем не публикуются.
